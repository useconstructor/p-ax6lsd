# Mesa Brava — fictional Mexican restaurant demonstration

An ingredient-led public website with a food typographic poster, horizontally browsable featured dishes, licensed chicken taco, cheese quesadilla and guacamole photographs, original ingredient illustrations, a complete filterable Turso catalog, and a dedicated receipt-style order flow with an accessible catalog drawer. All offerings and availability are explicitly illustrative; there are no prices, payments or real pickups.

Run `npm ci`, `npm run dev`. Production checks: `npm run lint`, `npx tsc --noEmit`, `npm run build`, `npm start`.

Runtime requires `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`. The database client connects lazily; missing credentials never trigger a substitute database. Catalog IDs and all previous orders, pickup slots and sessions are preserved. The explicitly labelled demonstration window spans 28 days (12:00–15:00 UTC), retaining five orders per 30-minute slot. The previous seven-day window was fully occupied; only future demonstration availability was added. Availability generation is idempotent; no retention or deletion behavior is introduced. Order writes enforce integer quantities of 1–20, future slots, availability, session ownership, origin validation, serialized slot capacity and payload-bound idempotency.

Deployed anonymous sessions use Secure, HttpOnly, Partitioned, SameSite=None cookies. HTTP loopback uses HttpOnly SameSite=Lax for local QA. Configure trusted additional application origins with `ALLOWED_ORIGINS`; application origin and supplied hosting site environment URLs are accepted. Tokens never appear in URLs. Drafts remain in React state and sessionStorage through navigation and reload; saved orders persist in Turso and recover on reload within the private browser session.

Art direction is retained in ignored `.design-evidence/`. Latest executed review evidence and the exported reproducible verifier are in `/tmp/constructor-quality/`. Run `node /tmp/constructor-quality/verify-interactions.cjs http://127.0.0.1:3100 /tmp/constructor-quality` against the running app. Its `verify({browser,baseUrl,evidenceDir})` export uses the supplied browser and URL, creates only explicitly named fictional test orders in the provided Turso database, retains all records and fails if required demonstration availability is absent. All 119 local assertions passed: desktop/mobile homepage-to-order journeys, actual catalog filters, add and quantity controls, modal focus containment and Escape, invalid/valid submission, exact saved receipt contents after reload, idempotency, private session isolation, origin/input/past-slot rejection, concurrent capacity, empty state, reduced motion and tablet layout. Required destination/success screenshots are saved there. Lint, TypeScript and production build pass. HTTPS cookie attributes and creation/recovery in the actual Constructor iframe after parent reload are separate deployment checks in `pending-deployment.json`; they were not claimed as verified by this HTTP run.

`ASSET-LICENSES.md` records the licensed local photographs/fonts and original illustrative assets. No commits, pushes or deployment are part of this task.
