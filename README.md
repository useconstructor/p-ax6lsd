# Mesa Brava — fictional restaurant demonstration

A complete Spanish public homepage reproducing the approved cantina reference: red taco poster, working featured rail, yellow ingredient assembly, real filterable catalog, HTML pickup receipt invitation and original illustrated footer. Dedicated menu, order and saved confirmation routes carry the same identity. The catalog, availability and imagery are explicitly examples; there are no prices, payments or real pickups.

Run `npm ci` and `npm run dev`. Production checks: `npm run lint`, `npm run build`; serve with `npm start`.

Runtime requires `TURSO_DATABASE_URL` and `TURSO_AUTH_TOKEN`. No substitute persistence is used. Existing catalog IDs, orders, pickup slots, capacities and session protections are preserved. The existing demonstration window spans 28 days (12:00–15:00 UTC), five orders per 30-minute slot. Date generation is idempotent and no records are deleted. Writes enforce integer quantities of 1–20, future slots, item availability, session ownership, request-origin validation, transactional capacity and payload-bound idempotency.

Deployed anonymous sessions use Secure, HttpOnly, Partitioned, SameSite=None cookies. HTTP loopback uses HttpOnly SameSite=Lax for local QA. Configure additional trusted origins with `ALLOWED_ORIGINS`. Private session tokens never appear in URLs. Temporary selections remain in React state and sessionStorage through navigation/reload; saved orders persist in Turso and recover within their private browser session.

Executed QA evidence is outside shipped source in `/tmp/constructor-quality/`; art direction is also copied to ignored `.design-evidence/`. `verify-interactions.cjs` exports `verify({browser,baseUrl,evidenceDir})` for independent execution against the host-supplied browser and URL. It verifies navigation, all six catalog records, category selection, add/quantity controls, dialog Escape/focus, invalid and valid submission, saved contents after reload, idempotent replay, session isolation, origin/item/quantity/date/capacity rejection, keyboard and reduced-motion behavior, and no horizontal overflow at 1440/768/390. Separate concurrent submissions verified exact capacity enforcement. QA creates explicitly labelled fictitious test orders and retains them. Production build and lint pass. Full-page homepage/order captures and invalid, open catalog, populated order and success states are saved there.

HTTPS cross-site embedding and partitioned session recovery after parent reload require host-environment verification; these are not claimed as tested by local HTTP checks. No commits, pushes or deployment were performed.
